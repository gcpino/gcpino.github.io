My bachelor's thesis was a convolutional network trained on real physics data — not a benchmark, not a tutorial. The trained weights, not the model itself, were the deliverable: they let us extract physical insight about the system that generated the data. That experience — building something in order to learn from it, not just to ship it — shapes how I work today.

These days I write C. Four single-header libraries cover FM demodulation, bounded memory, neural network inference, and AES-256 with GCM. Each ships with a published test vector suite (FIPS 197, NIST SP 800-38A, SP 800-38D) and a round-trip test. The hot path has zero dependencies — the metal is the point.

Systems & Memory

C

balloc

A small C library offering three pre-allocated memory strategies from a single header: arena (bump), pool (fixed-size), and heap (first-fit with coalescing). Bounded memory, predictable performance.

All buffers are reserved up front, so the hot path never calls the system allocator. Useful for embedded targets, real-time systems, and workloads where allocation latency matters. Benchmarked faster than glibc malloc on small allocations and pooled objects.

Signal Processing

C

sdr

A C library that demodulates FM broadcast from an int16 I/Q capture into a 16-bit PCM WAV. The full pipeline fits in ~600 lines: NCO, multi-stage decimation, atan2 discriminator, de-emphasis, and a WAV writer.

Ships a synthetic FM signal generator so the project is fully testable without RF hardware. The round-trip test synthesizes a 1 kHz tone, demodulates it, and verifies the recovered spectrum is essentially a pure tone.

Machine Learning

c-infer

A minimal neural network inference engine written from scratch in C. Designed to bridge the gap between Python-based training environments (like PyTorch) and execution on hardware-constrained edge devices where predictable memory and performance are critical.

The engine executes pre-trained models with a strict, pre-allocated memory footprint. It implements essential linear algebra operations directly, ensuring tight control over the hardware without relying on external libraries.

Cryptography

C

aes256

A single-header C11 implementation of AES-256 with the standard block modes (ECB, CBC, CTR) and an AES-256-GCM AEAD. No dependencies beyond libc. Verified against FIPS 197, NIST SP 800-38A, and SP 800-38D test vectors.

The cipher follows the FIPS 197 spec directly: SubBytes, ShiftRows, MixColumns, AddRoundKey. GCM uses a standard GHASH over GF(2^128) with a constant-time tag comparison in the open path. The whole library — block cipher, four modes, and tests — fits in roughly 400 lines of header.
